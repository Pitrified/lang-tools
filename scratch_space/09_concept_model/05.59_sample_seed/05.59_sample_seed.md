# Phase 5.59 - regenerate the committed sample seed from the real build

The committed seed under `data/bootstrap/` was hand-authored placeholder data from before
the first real OMW build: 4 concepts (`house`, `water`, `to eat`, `building`) whose ids
matched nothing in the corpus - all four had been rewritten by 5.55's re-slug, and the
glosses ("edificacao para morar") were written by hand, not carved from anything.
It is the fixture the webapp tests and `parquetize_seed.ipynb` read, and the slice
`lang-tutor` is meant to consume, so it should be a real slice of the real corpus.

This is an early piece of phase 9 ("regenerate fresh sample data from the pipeline"), done
now because the corpus just changed three times under it (5.55 re-slug, 5.57 junk drop,
5.58 curated glosses).

## What changed

**The seed is carved by the build, not written by hand.** `build_initial` already had a
`sample_data_fol` parameter and a `carve_sample` stage; the transform notebook simply never
passed it. It now carves into `data/bootstrap/lexicon/` - the corpus folder the store
reads - and a following cell exports those tables back to the committed
`data/bootstrap/*.jsonl`, so the JSONL source and the Parquet beside it agree and both come
from the pipeline.

**`carve_sample` ranks instead of taking the first N by id.** Sorting by id is stable but
arbitrary, and on the real corpus it produced a seed of `15 May Organization`, `1530s`,
`1750s` - technically valid, useless to every consumer the slice exists for. Concepts are
now ranked by what a consumer can do with them: most languages first, then having an
example sentence, then id.
The id tiebreak keeps the slice deterministic across rebuilds, and the ranking needs no
fallback branch: a build where nothing is rich sorts by id on its own.

## Result

| | before (hand-authored) | first id-ordered carve | ranked carve |
| --- | --- | --- | --- |
| concepts | 4 | 50 | 50 |
| lemmas | 301 | 157 | 587 |
| senses | 18 | 169 | 660 |
| concept relations | 1 | 0 | 1 |
| per-language lemmas | pt/en only | 71 en / 11 it | 123 en / 85 es / 143 fr / 111 it / 125 pt |
| first concepts | `house`, `water` (fictional ids) | `15 May Organization`, `1530s` | `a lot`, `abandon`, `abasement` |

The ranked slice is balanced across all five languages, carries real glosses and examples,
and every id exists in the corpus it came from.

One thing the seed **loses**: its single hand-authored false-friend edge. The pipeline
produces no false friends until phase 7, so a carved slice cannot contain one, and the
webapp's `/false-friends` endpoint now has no seed row to demonstrate. The webapp tests
compare API output against the store rather than fixed content, so they stay green; this is
demo coverage, not correctness. It comes back for free when phase 7 populates the table.

The seed files are Git LFS objects (`.gitattributes` routes all of `data/**` through LFS),
so the regenerated JSONL is stored the same way the previous seed was.

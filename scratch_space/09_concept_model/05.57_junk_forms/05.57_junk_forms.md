# Phase 5.57 - drop the placeholder and markup lemmas the 5.55 filter missed

A deterministic follow-on to [`05.55_llm_cleanup/05.55_llm_cleanup.md`](../05.55_llm_cleanup/05.55_llm_cleanup.md).
Reviewing the 5.55 gloss repair turned up three classes of non-word member form that the
5.55 `#` / `.C3.` wiki-anchor filter does not catch.
They are junk tokens, not words: the same category 5.55 already decided to drop in the
pipeline and rebuild, so this phase reuses that machinery rather than inventing anything.

No LLM, no review loop - the rule is exact and the count is known in advance.

## What is in the corpus today

Measured on the 2026-09-01 corpus (117,659 concepts / 321,097 lemmas / 491,845 senses).

| class | forms | senses | why it is junk |
| --- | --- | --- | --- |
| MultiWordNet gap markers | it `GAP!`, `PSEUDOGAP!` | 1,008 | MWN's markers for *"this synset has no Italian lexicalization"*, ingested as ordinary Italian noun lemmas. An Italian consumer can be handed `GAP!` as a word. |
| HTML-escaped wiki markup | 11 fr forms | 11 | `Milan &lt;!--gender?--&gt;`, `vitamine B&lt;sub&gt;6&lt;/sub&gt;`, `&lt;big&gt;&lt;big&gt;&lt;b&gt;=&lt;/b&gt;...` - the same WOLF derivation artifacts as 5.55's anchors, escaped rather than URL-encoded, so the `#` / `.C3.` markers miss them. |
| raw HTML tag | pt `<HTML>` | 1 | not a word in any language. |

Two more fr forms carry an HTML entity but are **recoverable, not junk**:
`fr&amp;eacute;n&amp;eacute;sie` (= `frénésie`) and
`Parc national de Sequoia &amp; Kings Canyon`.
Dropping them would throw away real words, so this phase **repairs** them instead - see
the rule below.

## Rule

Two changes in `ingestion/sources/omw.py`, both on the path `group_to_records` already
uses for the 5.55 drop:

1. **Unescape first.** Run each member form through `html.unescape` before anything else.
   That repairs the two recoverable forms (`fr&amp;eacute;n&amp;eacute;sie` -> `frénésie`,
   which merges into the `frénésie` lemma that already exists) and turns the 11 markup
   forms into plain `<...>` markup, which the next rule then catches.
   Blast radius is exactly the 13 entity-bearing forms - no other form in the corpus
   contains an HTML entity.
2. **Extend the malformed-form test.** Keep the `#` / `.c3.` substring markers, and add:
   - `<` as a substring marker (after unescaping: catches the 11 markup forms and pt
     `<HTML>`; the corpus has no legitimate form containing `<`);
   - `GAP!` / `PSEUDOGAP!` as **exact, case-insensitive** matches, never substrings -
     en `gap` and pt `Gap` are legitimate lemmas and must survive.

Dropped forms lose their would-be senses, as in 5.55. The concepts stay.

## Expected effect (predict, then verify)

- 15 lemmas dropped (2 gap markers + 11 markup + 1 `<HTML>`, and 1 of the 2 escaped forms
  disappears by merging into its clean twin rather than by being dropped).
- 1,020 senses dropped.
- **0 concepts orphaned** - every affected concept keeps at least one member in some
  language. This is the invariant the 5.55 drop set: a lemma-eating drop must not orphan
  a concept, and the gate's reconciliation check enforces it.
- 251 concepts lose their last Italian member. That is correct, not a regression: `GAP!`
  means the synset has no Italian word, so the honest corpus has no Italian member there.
- All four gate invariants stay green; `definition == lemma` stays 0 with the baseline
  at 0.

## Finding: applied gloss repairs do not survive a rebuild

The rebuild regenerated `concepts.parquet` from OMW and **silently reverted the 5.55
gloss repair** - the it gloss went back to "attenzione", the `llm` provenance tag went
back to `omw`, and `definition == lemma` went 0 -> 1, failing the gate on the freshly
built corpus.

This is the seam 5.55 named for slugs ("slugs are fixed in the pipeline and rebuilt,
never edited into the Parquet post hoc") and did not apply to glosses, on the reasoning
that gloss edits do not feed `concept_id`. True, but beside the point: a rebuild
regenerates every column, so any post-hoc edit is lost regardless of whether it touches
ids.

Recovered here by re-applying the archived accepted proposal
(`data/_raw/lexicon/staging/gloss_repair.applied-2026-09-01.jsonl`) - gate back to green,
1 row re-tagged `llm`. **That is a workaround, not the fix.** The fix is the decision
5.55's Q2 already made for the slug-qualifier table: accepted proposals become a small
committed JSONL that the *build* applies, so a rebuild reproduces the curated state
instead of erasing it. Until that exists, every rebuild silently drops accepted gloss
repairs and the only thing that catches it is the gate. Routed to phase 8; not built here
because it changes the maintenance loop's contract, which is more than a junk-form drop
should carry.

# Phase 5.5 - cleanup: re-cut the build around the OMW backbone

> The act step that follows the measure step. [`05.4_data_quality.md`](05.4_data_quality.md)
> named the defects and resolved the strategy (drop kaikki, frequency-as-signal, clean
> licensing); this plan executes it. It edits the pipeline and rebuilds the data, where
> 05.4 only looked. The approach: do not salvage the kaikki glosses, remove the whole
> enrichment path, and re-anchor the dataset on the concept / gloss / sense triple from
> OMW/ILI.

## The core decision

The dataset's core is three things, all from OMW and the ILI it links through:

- **Concept** - a language-independent meaning (an ILI-keyed synset group).
- **gloss** - one English definition per concept that carries real meaning, with a CILI
  English fallback for the gaps. Per-language glosses are not a launch priority.
- **Sense** - the lemma <-> concept edge, the only membership record, the home for
  frequency (phase 6) and the anchor for relations (phase 7).

Everything kaikki added sat outside that triple (lemma-only, no concept id) and brought in
junk plus CC-BY-SA. So the cleanup is a subtraction: remove kaikki, keep the triple clean,
then let phases 6/7/8 add signal on a sound base.

## Why remove kaikki instead of fixing the join

The first build (2026-06-18) showed the kaikki enrichment is not fixable in place:

- **62,612 of 117,659 concept glosses (~53%)** are kaikki-tagged - half the gloss surface
  riding on a sense-blind `(text, language)` join, not "enrichment only".
- **7,220 rows** have `definition == lemma`; many non-en glosses are bare English words,
  `PSEUDOGAP!` junk, or `form-of` notes stored under the wrong language (the `house`
  defect, [`05.4_data_quality/models_explained.md`](05.4_data_quality/models_explained.md)).
- It is the only CC-BY-SA source, capping the whole shipped corpus
  ([`05.4_data_quality.md`](05.4_data_quality.md) "emerging direction" (3)).

A sense-aware join would be real work to build and would still be CC-BY-SA. Removing the
path and accepting sparser non-en glosses (never the priority) gives a cleaner result, with
permissive backfill added later.

### Step 1 - remove kaikki from the ingestion code

**Status: done (2026-06-20).** Hard-deleted `sources/kaikki.py` and `wiktionary.py`
(+ their tests), dropped `_enrich_concepts`/`_enrich_lemmas` from `transform.py` (now
OMW-only, every row tagged `omw`), removed `fetch_kaikki`/`kaikki_path` and the kaikki
language map from `acquire.py`, cleaned both `__init__.py` exports, and pulled the
`fetch_kaikki` cells from `01_download.ipynb`. `SOURCE_KAIKKI` stays as a documented
**legacy** provenance value (no writer sets it). Added the standing guard test
`test_no_row_is_tagged_kaikki`. No kaikki-specific dependency existed (it used stdlib
`json`/`urllib`), so none was dropped; `wn` stays for OMW. Suite green: 146 passed,
ruff clean, pyright 0 errors.

Hard delete. Remove the enrichment path entirely, not behind a flag.

- Delete `_enrich_concepts` and the kaikki gloss/example top-up from
  [`transform.py`](../../src/lang_tools/lexicon/ingestion/transform.py); `group_to_records`
  builds `Concept.definitions` from OMW glosses only.
- Delete the kaikki source module and wiktextract loader (`WikiRecord`, `WikiSense`,
  `load_wiktionary_jsonl`, `KaikkiEntry`) from
  [`sources/`](../../src/lang_tools/lexicon/ingestion/sources/) and its call sites.
- Drop the kaikki download/manifest entries from the build config and any kaikki path in
  `_build.json`; drop now-unused deps.
- `Lemma.examples`, `Lemma.topics`, and the `"kaikki"` provenance tag become unused by the
  OMW path. Leave the model fields (re-filled later from Tatoeba / OMW), but no writer sets
  them in this build. The `source` enum keeps `kaikki` as a legacy value only.
- Tests: delete the kaikki ingestion tests; add a guard test that no built row carries
  `source == "kaikki"`.

*Propagate to:* 05_ingestion.md (the ingestion plan of record loses the enrichment leg),
tracking.md.

### Step 2 - guarantee the English gloss, add the CILI fallback

**Status: done (2026-06-20), fallback kept as a dormant safety net.**
`group_to_records` fills a concept's English gloss from the ILI's CILI definition when OMW
left it blank, tagging that concept `cili` (new permissive provenance value defined in
`sources/omw.py`); `transform` threads the per-concept tags through. `acquire.download_omw`
also downloads the `cili` resource. Implementation note: in `wn` 1.1.0 `synset.ili` is a
bare id string, not an object, so glosses are read via the loaded ILI resource (streaming
`wn.ili.find_ilis()`, keyed by ILI id) rather than `synset.ili.definition()`; absent the
resource the fallback just does not fire. Tests cover the fallback firing, not firing when
OMW has an English gloss, and the cili tag threading through `transform`.

**Verified finding (the five-language build, 2026-06-20):** the fallback fired **0 times** -
provenance is `{omw: 117659}`, no `cili`, even though CILI loaded fine (117,659 ILI glosses).
This is structural, not a bug: an ILI exists only because a Princeton/English synset does,
and `omw-en` (Princeton WN 3.0, the source CILI derives from) has ~100% gloss coverage, so
every ILI-backed concept already has an English OMW gloss. Concepts that lack an English
gloss are the non-English monolingual ones, which are ILI-orphans (grouped by synset id) the
CILI lookup cannot reach anyway. So the English gloss is effectively guaranteed by `omw-en`;
the CILI fallback only matters for a future build that excludes the English wordnet. We
**keep it** as a documented dormant safety net (cheap: one ~1s ILI load). Suite green: 149
passed, ruff clean, pyright 0 errors.

With kaikki gone, the English gloss is the central field. Make it solid.

- Keep the OMW English gloss as primary (coverage is ~100% today).
- Add a CILI English gloss fallback: when a concept is ILI-backed and its English OMW gloss
  is blank, fill from `synset.ili.definition()` (permissive, already reachable via `wn`).
  This is the clean replacement for what kaikki pretended to do.
- Tag fallback glosses `source = "cili"` (new permissive provenance value).
- Per-language (non-en) glosses: keep only real OMW glosses, leave the rest empty. Sparser
  is correct; do not fabricate. Target-language backfill is later and optional.

*Propagate to:* 05_ingestion.md, 05.4 metadata_catalog.md (CILI promoted from "dropped"),
10_licensing_docs.md (CILI is permissive).

### Step 3 - one ingestion loader per dataset

Re-cut ingestion so each source is a small, isolated, single-responsibility loader, with no
source reaching across into another's rows. The kaikki problem came from a cross-source join
with no sense alignment; the new shape forbids that by construction.

| Source | Role | Unit | License | Status this phase |
| --- | --- | --- | --- | --- |
| **OMW via `wn`** | backbone: concepts, glosses, senses, members, POS | synset (ILI-linked) | permissive (per-lexicon, verify) | the build |
| **CILI** | English gloss fallback only | ILI record | open | Step 2 |
| **Tatoeba** | example sentences (lemma-join, flagged sense-blind) | sentence | CC-BY | deferred -> phase 6/8 |
| **Wikidata Lexemes** | optional structured sense/gloss source | lexeme/sense | CC0 | deferred -> phase 8 probe |

Rules that hold for every loader, now and later:

- A loader either creates backbone rows (OMW only) or annotates existing rows by a declared
  key; it never invents a gloss for a sense it cannot identify.
- Cross-source fills are sense-aware or they do not ship. A lemma-only join like Tatoeba is
  allowed for examples (sense-tolerant), never for glosses.
- Every written field carries its own `source` tag and license bucket. Per-row provenance
  stays the licensing source of truth (phase 10).

*Propagate to:* 05_ingestion.md (the loader contract), 05.4 other_datasets.md, 10.

### Step 4 - promote the permissive OMW fields we already have

Dropping kaikki lets us lean harder on OMW, which carries good data we currently discard
([`05.4_data_quality/metadata_catalog.md`](05.4_data_quality/metadata_catalog.md) "promote
shortlist"). Pull the zero-license-cost fields into the build now so phases 6/7 start from
real data, not nulls:

- **`synset.examples()`** -> seed example sentences with no CC-BY-SA tax (the replacement
  for kaikki examples). *(feeds 6/8)*
  - **Where examples live.** An example shows a lemma used in one sense, so the natural home
    is the `Sense` edge, alongside frequency and CEFR (the same polysemy logic from phase 2).
    The constraint is source granularity: OMW `synset.examples()` are concept-level (one
    synset, no per-member split) and Tatoeba examples are lemma-level (sense-blind). So the
    target home is `Sense`, but each source attaches at the granularity it actually has -
    concept-level OMW examples fan out to that concept's senses, lemma-level Tatoeba examples
    attach to the lemma and are flagged sense-blind - rather than inventing a sense link the
    source does not provide. Final model placement is a phase-2/6 detail; noted here so
    examples are not silently dropped back onto a bare `Lemma`. Will consider data duplication
    and handling in that phase.
- **`synset.lexfile`** (lexicographer category, e.g. `noun.motion`) -> a coarse semantic
  class for clustering / difficulty. *(feeds 6/8)*
- **`sense.id` + `sense.counts()` / `tag_count`** -> the only direct per-sense frequency
  signal. `tag_count` comes from **SemCor**, the WordNet sense-tagged corpus (English only):
  it records how often each sense was annotated in running text, which phase 6 uses as the
  weights to split a lemma's token frequency across its senses. Relevant to this phase only
  in that the build must carry `sense.id` through so phase 6 can join those weights; the
  weighting itself is phase 6. *(feeds 6)*
- **`synset.hypernyms/hyponyms` + sense `antonyms`** -> the relation graph the
  `ConceptRelation` / `FalseFriendRelation` stubs already expect. Capture the edges in the
  same OMW traversal. *(feeds 7)*

Keep frequency as 05.4 decided: a priority/ranking signal, never a hard cap. No row is
deleted for being rare; connectivity and learning value override raw frequency
([`06_frequency_complexity.md`](06_frequency_complexity.md)). The same two signals also
direct the cleanup effort: frequency and graph connectivity rank which concepts and glosses
the Step 5 LLM pass enriches first, so a limited enrichment budget lands on the words that
matter most instead of the long tail.

*Propagate to:* 06_frequency_complexity.md, 07_relations.md, 05.4 metadata_catalog.md.

### Step 5 - LLM cleanup pass

With the base sound, use the LLM where OMW can verify it. This is the phase-8 maintenance
machinery, run as a one-time cleanup over the rebuilt corpus:

- **Slug dedup / legibility** - re-pick `_pick_slug_source` for the ~27% colliding slugs
  (ids stay unique via `hash[:12]`; readability only).
- **`definition == lemma` repair** - for the residual OMW cases (kaikki's 7,220 are gone),
  generate an English gloss grounded in the synset's ILI gloss and members; flag, do not
  silently overwrite.
- **Orphan / empty concepts** - review single-member, no-gloss-in-any-language concepts;
  merge or drop with an audit trail.
- **POS review** - moot for kaikki (gone); keep the OMW-internal odd/unmapped-POS review
  (`p/x/u` -> null) from check 4.
- **Optional target-language gloss backfill** - if a consumer needs non-en glosses,
  LLM-write them guided by (never copying) external text, so the output is original and
  license-clean (brainstorm option c). Per language, on demand, not at launch.

LLM autonomy stays propose-for-review for anything that changes meaning; auto-apply only
mechanical fixes (slugs).

*Propagate to:* 08_maintenance.md (this becomes its concrete first-run checklist).

### Step 6 - maintenance loop and regression harness

Make cleanup repeatable rather than a one-off.

- Re-run the [`05.4_data_quality`](05.4_data_quality/) notebook checks against the rebuilt
  corpus as a gate: the kaikki-tagged share must be 0%, `definition == lemma` must drop
  sharply, dangling-edge / lemma-without-sense must stay 0.
- Wire those checks as a regression harness re-run after every maintenance pass and every
  re-ingestion, so quality is measured each time, not assumed.
- Decide cadence and trigger (manual CLI vs scheduled) and how runs are logged for the
  dataset card. Re-ingestion of updated OMW is a smart merge against the curated Parquet
  keyed on `source` (deferred per phase 5).

*Propagate to:* 08_maintenance.md, 09_sample_and_consumer.md (regenerate the sample slice
from the clean build, referentially closed).

## What we accept

- Non-en gloss coverage drops to real OMW coverage (es ~70% goes lower once the kaikki
  top-up is removed). This is intended: the removed glosses were low-quality or wrong-sense.
- The dataset gets smaller, which is the goal of a cleanup.
- Target-language glosses become a deliberate later investment (LLM, license-clean), not a
  by-product of a bad join.

## Done when

- No row in the rebuilt corpus carries `source == "kaikki"`; the kaikki loader is gone from
  the codebase.
- English gloss coverage stays ~100% (OMW + CILI fallback); `definition == lemma` is near
  zero; dangling edges / lemmas-without-sense are 0.
- OMW examples / lexfile / sense keys / relation edges are populated (feeding 6/7).
- The 05.4 check harness passes as a gate and is re-runnable.
- `uv run pytest && uv run ruff check . && uv run pyright` passes.
- The seven steps are propagated into 05/06/07/08/09/10 and [`tracking.md`](tracking.md).

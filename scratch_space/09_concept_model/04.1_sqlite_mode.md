# Phase 4.1 - SQLite-only runtime engine

## Overview

Collapse the phase-4 store to a **single SQLite engine** and remove the in-memory
resident mode entirely. Sequenced **before phase 5** so the runtime engine is
settled and phase 5 (and everything after) is written once against the final
engine instead of against resident dicts we are about to delete. Context:
[`04_store_layer.md`](04_store_layer.md) ("Runtime modes"), the phase-3 numbers
(full graph ~1.9 GB resident; SQLite point lookups ~30 us).

This **supersedes the resident/SQLite dual-mode decision** in phase 4 (which stays
`done` - it was right at the time; this is the follow-up simplification once we
committed to SQLite-only).

## Why before phase 5

Under SQLite-only, phase 4's resident dicts, `_hydrate()`, the `LexiconStoreMode`
enum, the `SqliteModeNotImplementedError` stub, and the bootstrap-CSV→resident load
path are all dead code. Doing the swap first means:

- one engine, one code path - no mode selection, no eager-vs-on-demand hydration
  split, no ~1.9 GB ceiling to reason about;
- phase 5's writer + store-load `Done when` target the final engine, no rework;
- the surface `lang-tutor` consumes (phase 9) is settled earlier.

Cost: SQLite mode needs *some* data to run on before phase 5 produces the real
corpus (see "Bootstrap data source").

## Goals

1. Build a `data/lexicon/lexicon.sqlite` from the source-of-truth Parquet (tables +
   indexes; the phase-4 in-memory look-aside indexes become SQL indexes). Built,
   not shipped - regenerable from Parquet, the `.sqlite` is gitignored (phase-3
   decision: do not commit a DB blob).
2. Reimplement the full `LexiconStore` query surface against SQLite: point lookups
   by id, adjacency (senses-for-lemma/concept, false friends, concept relations),
   filtered lemma reads - **same signatures** as today, so callers/tests/webapp do
   not change shape.
3. **Remove resident mode**: delete the resident dicts, `_hydrate()`,
   `LexiconStoreMode`, `SqliteModeNotImplementedError`, and the dual-mode branching.
   Back-ref navigation (`resolve_*`) becomes bounded on-demand SQLite hydration
   (1-2 hops, opt-in per call, no shared-instance identity) per the phase-4
   correction.
4. Keep the webapp lemma/concept APIs green throughout.

## Bootstrap data source: a hand-authored sample (resolved)

Removing resident mode also removes the current "load bootstrap lemma CSVs into
dicts" path that keeps the webapp lemma API green. SQLite mode needs data in the
`.sqlite`. We have everything needed to author a small sample **now** (the
`concept_id`/`lemma_id`/`sense_id` constructors, the models, and the codec all
exist; no OMW required for a handful of plausible entries). Plan:

```
committed sample JSONL  (lemmas/concepts/senses/false_friends/concept_relations)
   → model_from_row      (codec validation, pure-python, no pyarrow)
   → build SQLite        ← the 4.1 engine's job
```

As built, the sample path goes JSONL seed → models → SQLite **directly** (no
intermediate sample Parquet). The seed → Parquet round-trip (`import_table`)
stays available as a manual tool, and the Parquet branch of `from_data_fol` is
what phase 5 uses once `data/lexicon/` exists.

- **Source of the rows.** Reshape the existing `data/bootstrap/*.csv` lemmas into
  `lemmas` JSONL (thin shape - `csv_loader` already maps them), and hand-author a
  small coherent concept/sense set: a few concepts with pt/es/fr/it/en lemmas +
  their `Sense` edges + one false-friend pair + one concept relation. This is
  **richer than lemma-only on purpose** - it gives 4.1's SQLite adjacency queries
  (senses-for-lemma/concept, false friends, relations) real parity tests instead of
  empty tables, and doubles as the phase-9 sample seed.

- **Format: JSONL, not CSV.** The new model has nested fields (`Concept.definitions`
  per-language dict, `Lemma` examples list) that CSV cannot hold cleanly; JSONL is
  exactly the row shape `import_table` consumes, and a ~50-row sample is diffable in
  normal git (the phase-3 "no committed JSONL" rule targeted 50k-row tables).

- **Parquet stays the single source of truth** (consistent with the cross-cutting
  decision). The committed JSONL is a readable *seed/input* that generates the
  sample Parquet - the same role the raw OMW/kaikki cache plays for the full corpus,
  just committed because it is small. Not a competing truth: if seed and Parquet
  drift, Parquet wins; `export_table` refreshes the seed. (The "JSONL is never
  committed" wording in `corpus.py` gets a carve-out for this sample-seed dir.)

- Phase 9 may later replace this hand-authored seed with a slice carved from the
  phase-5 full corpus; until then it is the committed sample.

## Out of scope

- The initial ingestion (phase 5) and the deferred re-ingestion merge.
- DuckDB stays inspect/QA-only (`corpus.inspect_table`) - not a runtime engine,
  unchanged.
- Frequency/CEFR (6), relations (7), maintenance (8).

## Resolved at execution

- **Mode selection collapsed to none.** No second engine to choose: `from_models` /
  `from_data_fol` always build one SQLite database. `LexiconStoreMode`,
  `SqliteModeNotImplementedError`, `_hydrate()`, and the list-based constructor are
  deleted.
- **Sample Parquet: built on demand, not committed.** `data/` is gitignored and
  git-LFS is not materialized here, so committing a Parquet blob is the wrong call.
  The store builds SQLite directly from the committed JSONL seed (Parquet preferred
  only when phase 5 has produced `data/lexicon/`). `sqlite3` is in the standard
  library, so the seed path needs no `store` extra - preserving "lang-tutor reads
  the lemma surface without pyarrow".
- **Back-references became opt-in.** `hydrate_lemma` / `hydrate_concept` /
  `hydrate_sense` fill the excluded back-refs on demand (bounded 1-2 hops, fresh
  instances, no shared-instance identity); `resolve_*` still raises until hydrated.

## Done when

- A small hand-authored sample (committed JSONL seed → Parquet) covers lemmas plus
  a few concepts/senses/edges, exercising the adjacency queries.
- `LexiconStore` answers the entire phase-4 query surface from a Parquet-built
  `.sqlite`; resident mode and the mode seam are gone.
- The webapp lemma/concept APIs are green on the SQLite engine.
- `docs/library/lexicon.md` + `frozen_api.md` updated to drop resident/mode wording.
- `uv run pytest && uv run ruff check . && uv run pyright` passes.
